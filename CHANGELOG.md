# Changelog

All notable changes to this project are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.0] - 2026-11-05

A rewrite around calls instead of packets: sipcurious is now a set of subcommands for Voice/SIP teams who have a pcap of a broken call and need to know what happened and why.
Command-line compatibility with v1 is **not** preserved; see [Migration from v1](#migration-from-v1).

### Added

- **Subcommands** (`sipcurious <command> [flags] CAPTURE...`): `messages` (one row per SIP message; aliases `search`, `grep`), `calls` (one row per Call-ID; alias `dialogs`), `show` (full message text, `--headers-only`, `--sdp-only`), `flow` (ladder diagrams: ASCII, Mermaid, SVG; alias `ladder`), `diagnose` (diagnostic rules, `--fail-on`; alias `check`), `rtp` (RTP streams; alias `streams`), `stats` (ASR/ACD, timings, peak concurrency, top-N), `export` (pcap/pcapng of the matching calls), `report` (HTML or Markdown), `rules`, `fields` (the filter language), `help`, `completion` (bash, zsh, fish), `version`. `sipcurious help` is the authoritative list.
- **Call model** (`internal/call`): calls grouped by Call-ID with kind (call, registration, subscription, message, options, other), state (completed, answered, cancelled, failed, redirected, no-response, in-setup, ok), final response, PDD / ring / setup / talk times, who ended the call, `Reason` header, retransmission and missing-ACK detection, forking, user agents and negotiated media from SDP (offer/answer, delayed offer, early media, hold). Definitions: [docs/definitions.md](docs/definitions.md).
- **RTP analysis** (`internal/rtp`): RTP/RTCP detected on any UDP port without SDP, per-stream loss, reordering, duplicates, RFC 3550 jitter, maximum gap, RFC 4733 DTMF events, RTCP SR/RR summary, E-model R factor and MOS estimate; RTP streams are correlated to calls through the SDP endpoints. Verified against `tshark -z rtp,streams`.
- **Filter language** (`--where`, `-w`): typed boolean expressions over messages and calls (`from ~ alice and status >= 500`, `duration > 30s and not has_media`), CIDR matching, ranges, regular expressions, arbitrary headers, errors with a caret under the offending token. Fields are a registry. Reference: [docs/query.md](docs/query.md).
- **Filter flags** shared by every capture command: `--from`, `--to`, `--callid`, `--uri`, `--method`, `--status` (code or class such as `4xx`), `--src-ip`, `--dst-ip` (address or CIDR), `--since`, `--until`, `--case-sensitive`.
- **Output formats**: `table`, `csv`, `json`, `ndjson`, `markdown`, `html` through `--format`/`-F`; `--extra`, `--utc`, `--color auto|always|never` (honours `NO_COLOR`), `--output`/`-o`, `--limit`, `--quiet`/`-q`, `--no-rtp`. Untrusted capture text is sanitised for every format (no terminal escape injection, safe HTML/Markdown/CSV).
- `calls` flags `--failed`, `--answered`, `--kind`, `--state`, `--sort start|duration|pdd|setup|mos`, `--top N`; `messages --count`.
- **Capture reader** (`internal/capture`) with a protocol-agnostic handler pipeline: pcap (micro/nanosecond, both byte orders, libpcap-modified), pcapng (several interfaces and link types), gzip, standard input, Ethernet/VLAN/Q-in-Q/SLL/SLL2/raw IP/BSD loopback, IP-in-IP and GRE tunnels, IPv4 and IPv6 fragment reassembly, **real TCP stream reassembly** for SIP (several messages per segment, messages over several segments, retransmission dropping, resynchronisation), SCTP DATA chunks, 30 M packets/s decode throughput on the benchmark machine ([docs/architecture.md](docs/architecture.md)).
- **Several capture files, directories and shell globs** in one run (`sipcurious calls captures/`), read in parallel and merged by timestamp.
- Deterministic demo captures with documented facts (`testdata/samples`, generated by `internal/pcaptest`) and 50 real and derived captures (`testdata/realworld`), with expectations derived from tshark/tcpdump.
- Documentation: [README.md](README.md) (quickstart, real examples), [docs/usage.md](docs/usage.md) (command reference, exit codes, environment, completion, piping), [docs/cookbook.md](docs/cookbook.md) (17 troubleshooting scenarios with real output), [docs/architecture.md](docs/architecture.md) (layers, concurrency, performance, extension recipes), [docs/query.md](docs/query.md), [docs/capture-formats.md](docs/capture-formats.md), [docs/definitions.md](docs/definitions.md); `AGENTS.md` rewritten for v2.
- GitHub Actions: `ci.yml` runs `gofmt -l`, `go vet` and `go test -race` on Linux, macOS and Windows; `release.yml` builds on a `v*` tag static (`CGO_ENABLED=0`) binaries for linux, darwin and windows on amd64 and arm64, archives them (tar.gz, zip for windows) with a `SHA256SUMS` file and publishes a GitHub release with the notes from this changelog.
- `make dist` builds the same release artifacts into `./dist` (`PLATFORMS="linux/amd64 darwin/arm64"` narrows it, `VERSION=` stamps the version).

### Changed

- **Go 1.27** or newer is required (`go 1.27.0` in `go.mod`).
- **Dependencies are Go modules** (`go.mod`, `go.sum`); the `dep` files (`Gopkg.toml`, `Gopkg.lock`) are gone. The only third-party dependency is `github.com/gopacket/gopacket`, pure Go.
- **Filters are ANDed** (v1.1 reported a message once per matching `--to`/`--from`/`--callid` filter, i.e. OR).
- **Text filters match the whole header value** (display name, URI, tag), v1 compared only the user part of the URI. They are case-insensitive substring matches unless `--case-sensitive`.
- **Timestamps keep milliseconds** in table output (`2026-03-04T10:00:00.250Z`, v1 truncated to seconds); CSV/JSON keep the full captured precision. Local time zone by default, `--utc` for UTC.
- **stdout carries data only.** The summary line (`sipcurious: read 1 file, 507 packets, 7 SIP messages ...`), warnings and errors go to stderr with a `sipcurious: ` prefix; v1 printed `Found N packets` and errors on stdout.
- **Exit codes**: 0 success (also "no matches"), 1 runtime error (unreadable capture, write failure), 2 usage error (unknown command or flag, bad expression), 3 findings at or above `--fail-on`, 130 interrupted. v1 exited with -1 (255) on every error.
- SIP is recognised by its start line on **any port and transport**, parsed by sipcurious' own forgiving parser (no gopacket SIP layer, no `siprocket`).
- A capture that is cut off mid-record is **read up to the cut** and a warning is printed (no failure).
- `testdata/aaa.pcap` moved from `cmd/sipcurious/aaa.pcap`.

### Removed

- The flat flag interface (`sipcurious --file ... --view ...`): the first argument is now a command.
- `--view` (use the commands). The root-level `--help` flag: use `sipcurious help` or `sipcurious <command> --help`.
- The v1 sources `cmd/sipcurious/{parser,search,util}.go` and, with them, the unreleased intermediate 1.x packages `internal/dialog`, `internal/filter` and `report.Packets/Dialogs`.
- `dep` (`Gopkg.toml`, `Gopkg.lock`), Travis (`.travis.yml`) and Scrutinizer (`.scrutinizer.yml`) configuration.
- Dependencies `github.com/marv2097/siprocket` and `github.com/sotoz/gopcap`.

### Fixed

- Messages split over several TCP segments, and several messages in one segment, are now reported completely (v1 had no TCP reassembly: only the first message of a segment was reported).
- IPv4/IPv6 fragmented SIP over UDP is reassembled instead of lost.
- Captures with `caplen > origlen` records, big-endian or nanosecond pcap, pcapng stored under a `.pcap` name and raw-IP link types are read correctly.
- Keep-alive datagrams (`\r\n\r\n`, `hello` payloads) and HTTP/TLS traffic on port 5060 are not SIP messages (covered by real captures in `testdata/realworld`).
- Half-captured header lines in snaplen-truncated packets no longer produce wrong Call-IDs.
- Compact header names (`i`, `f`, `t`, `m`, `v`) and folded multi-line headers are understood.

## Migration from v1

v1 (v1.1 and the unreleased 1.x work that grew `--view`, `--format` and the IP filters) had a single command with flags; v2 has subcommands, and the **command name must come first**. A v1 invocation maps like this:

| v1 | v2 |
|---|---|
| `sipcurious --file x.pcap` | `sipcurious messages x.pcap` (positional) or `sipcurious messages --file x.pcap` / `-f x.pcap` (repeatable; a directory or `-` for stdin also works) |
| `--view packets` (default) | `messages` (alias `search`); `show` prints the full text of the messages |
| `--view dialogs` | `calls` (alias `dialogs`) |
| `--view ladder` | `flow` (see `sipcurious help flow`) |
| `--format table\|csv\|json` | `--format` / `-F` with `table` (default), `csv`, `json`, plus `ndjson`, `markdown`, `html`; the Mermaid ladder output belongs to the `flow` command (`sipcurious help flow`) |
| `--to X`, `--from X`, `--callid X` | unchanged names, but they now match the **whole header** (v1: URI user only) and are **ANDed** (v1: ORed) |
| `--uri X`, `--src-ip`, `--dst-ip`, `--case-sensitive`, `--utc` (added during the unreleased 1.x work) | unchanged |
| `--unique` | `messages --unique`: the first matching message **of every Call-ID**. In v1.1 it kept only the **first match of the whole run** (the unreleased 1.x work already did it per Call-ID) |
| `--extra` (v1.1: add the Contact column) | `--extra` shows the extra columns (Src, Dst, Contact, URI, File#Index, UA); CSV/JSON always carry all columns |
| `-help` | `sipcurious help`, `sipcurious help <command>` |
| (none) | `--where EXPR` for anything the sugar flags cannot say, e.g. `-w 'from ~ alice and status >= 500'` (see [docs/query.md](docs/query.md)) |

Examples:

```
v1: sipcurious --file my_trace.pcap --to 12345 --from 67890
v2: sipcurious messages --to 12345 --from 67890 my_trace.pcap          # both must match now
v2: sipcurious messages -w 'to ~ 12345 or from ~ 67890' my_trace.pcap  # v1's OR behaviour

v1: sipcurious --callid 29858 --unique --file a.pcap
v2: sipcurious messages --callid 29858 --unique a.pcap

v1: sipcurious --view dialogs --src-ip 10.0.0.0/8 a.pcap b.pcapng
v2: sipcurious calls --src-ip 10.0.0.0/8 a.pcap b.pcapng
```

Behaviour changes that can break scripts:

- **Semantics**: OR becomes AND; text filters match the whole header (a `--to 12345` that matched only `sip:12345@...` in v1 now also matches a display name or tag containing `12345`); `--unique` is per Call-ID.
- **Streams**: v1 wrote `Found N packets` / `No Packets found ...` / `error: ...` to **stdout**. v2 writes only data to stdout and the summary, warnings and errors to stderr (`sipcurious: 5 messages matched`). Scripts that grepped for "Found" must read stderr or use `messages --count` (prints just the number on stdout).
- **Exit codes**: errors exit with 1 (runtime) or 2 (usage) instead of 255; "no matches" is still 0. Exit 3 means findings were reported.
- **Output shape**: the table is space-padded (no tabs) and has the columns `Timestamp Info Call-ID From To`; the header names `CallID` became `Call-ID`. Timestamps have millisecond precision (`2026-03-04T10:00:00.250Z`), and CSV/JSON field names are lower snake case (`call_id`, `file_index`).
- **Capture scope**: SIP over TCP is now parsed (v1 reported at most the first message of a segment); more messages therefore appear for the same capture.
- **Building**: Go 1.27 or newer is required. `dep ensure` is gone; use `go build -o sipcurious ./cmd/sipcurious` or `make build`. Library import paths changed: everything is under `internal/`, so there is no importable Go API.
